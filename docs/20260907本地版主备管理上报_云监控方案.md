# 云监控本地版主备管理上报方案（单机版）

## 目标

- 云监控先建立一个主备管理归属，再接收当前机器主备管理插件的注册、状态、切换任务和日志。
- 当前只考虑一台机器的上报和展示，不读取、不等待、不判断备用机状态。
- 云监控展示当前机器是主机还是备机、当前自检状态、最近切换任务和执行日志。
- 后续需要监控两台机器时，再扩展对端注册、双机聚合和双主/双备判断。

## 云监控职责

- 创建单机主备管理归属。
- 接收当前机器注册，并保存本机状态。
- 接收当前机器的自检、切换任务摘要和日志增量。
- 按当前机器的状态生成列表展示状态。
- 提供切换任务详情和日志查看。

云监控不提供切换角色按钮，不创建本机切换任务，不控制继续、暂停、取消，也不读取备用机状态。

## 数据结构

### 主备管理归属

存储位置：SQLite 表 `ha_pair`

用途：当前机器的主备管理归属，也是插件上报的归属。

```jsonc
{
  "pair_id": "HA_GROUP_001",       // 云监控创建后提供给当前机器插件
  "pair_name": "HA_GROUP_001",     // 不单独填写，默认等于 pair_id

  "status": "unknown",             // normal、warning、danger、switching、unknown
  "status_text": "等待当前机器上报",
  "last_report_at": "",

  "api_secret": "",                // 云监控生成，插件注册成功后静默保存
  "addtime": "2026-09-07 10:00:00",
  "update_time": "2026-09-07 10:00:00"
}
```

约束：

- `pair_id` 全局唯一。
- 当前一个 `pair_id` 只维护已接入的当前机器，不要求注册备用机。
- `status` 和 `status_text` 只根据当前机器最新上报生成。

### 当前机器状态

存储位置：SQLite 表 `ha_host_state`

用途：保存当前本地版插件最新一次上报的角色、自检和切换状态。

```jsonc
{
  "pair_id": "HA_GROUP_001",
  "host_id": "H_LOCAL_20260907100000_A1B2C3D4",
  "host_name": "主机A",
  "host_ip": "192.168.1.10",

  "role": "master",                // master、standby、unknown
  "online_status": "online",        // online、offline、unknown
  "health_status": "normal",        // normal、warning、danger、unknown
  "collect_status": "success",      // success、failed、partial、unknown
  "collect_method": "local",
  "site_scope": "local",

  "health_detail": {
    "health_text": "正常",
    "checks": []
  },

  "switch_task_id": "TASK_20260907_100000_A1B2C3",
  "switch_status": "running",      // idle、running、paused、failed、success、cancelled
  "current_step": "启动 OpenResty",
  "next_step": "标记为主机",
  "last_error": "",
  "log_path": "/www/server/jh-monitor/logs/ha_switch/TASK_20260907_100000_A1B2C3.log",

  "last_report_at": "2026-09-07 10:05:00",
  "update_time": "2026-09-07 10:05:00"
}
```

唯一约束：`pair_id + host_id`。

### 切换任务

存储位置：SQLite 表 `ha_switch_task`

用途：接收当前机器插件上报的一次切换任务摘要；不保存每一步完整日志。

```jsonc
{
  "switch_task_id": "TASK_20260907_100000_A1B2C3",
  "pair_id": "HA_GROUP_001",
  "host_id": "H_LOCAL_20260907100000_A1B2C3D4",

  "target_role": "master",
  "run_state": "running",          // pending、running、paused、failed、success、cancelled
  "status": "switching",            // normal、warning、danger、switching、unknown
  "status_text": "正在启动 OpenResty",

  "current_stage_title": "主机正式上线",
  "current_step": "启动 OpenResty",
  "next_step": "标记为主机",
  "last_error": "",
  "step_summary": [
    {"key": "master_online", "title": "主机正式上线", "state": "running"}
  ],

  "log_path": "/www/server/jh-monitor/logs/ha_switch/TASK_20260907_100000_A1B2C3.log",
  "addtime": "2026-09-07 10:00:00",
  "update_time": "2026-09-07 10:05:00",
  "finish_time": ""
}
```

唯一约束：`switch_task_id`。

### 切换日志

存储位置：`/www/server/jh-monitor/logs/ha_switch/TASK_xxx.log`

用途：保存当前机器插件上报的日志增量；云监控从文件读取日志，不建立日志 SQLite 表。

```text
[2026-09-07 10:00:10] [info] [master_online/mysql_online] 开始执行正式上线前确认 MySQL
[2026-09-07 10:00:20] [info] [master_online/mysql_online] 步骤执行完成
```

日志幂等键：`switch_task_id + seq`。云监控只追加尚未写入的序号，避免插件重试造成重复日志。

## 接口设计

### 创建单机归属

接口：`POST /ha/api/local/pair/create`

用途：云监控管理页面先创建单机主备管理归属。创建后才允许当前机器插件注册和上报。

请求：

```jsonc
{
  "pair_id": "HA_GROUP_001"
}
```

处理规则：

1. 校验 `pair_id` 非空且未被使用。
2. 写入 `ha_pair`。
3. `pair_name=pair_id`，`status=unknown`，`status_text=等待当前机器上报`。
4. 生成该归属的 `api_secret`。

### 插件注册当前机器

接口：`POST /ha/api/local/register`

请求：

```jsonc
{
  "pair_id": "HA_GROUP_001",
  "api_secret": "主备管理归属创建时生成的密钥",
  "host_id": "H_LOCAL_20260907100000_A1B2C3D4",
  "host_name": "主机A",
  "host_ip": "192.168.1.10",
  "role": "standby",
  "collect_method": "local",
  "site_scope": "local"
}
```

处理规则：

1. 校验 `pair_id` 已存在，校验 `api_secret`。
2. 按 `pair_id + host_id` 新增或更新 `ha_host_state`。
3. 当前不要求注册备用机，也不校验对端机器是否存在。
4. 返回已确认的 `pair_id` 和 `api_secret`；插件静默保存密钥，不增加页面输入项。

### 插件上报当前状态、任务和日志

接口：`POST /ha/api/local/report`

请求：

```jsonc
{
  "pair_id": "HA_GROUP_001",
  "api_secret": "主备管理归属密钥",
  "host_id": "H_LOCAL_20260907100000_A1B2C3D4",
  "host_name": "主机A",
  "host_ip": "192.168.1.10",

  "role": "master",
  "online_status": "online",
  "health_status": "normal",
  "collect_status": "success",
  "collect_method": "local",
  "site_scope": "local",
  "health_detail": {
    "health_text": "正常",
    "checks": []
  },

  "switch_task": {
    "switch_task_id": "TASK_20260907_100000_A1B2C3",
    "target_role": "master",
    "run_state": "running",
    "status": "switching",
    "status_text": "正在启动 OpenResty",
    "current_stage_title": "主机正式上线",
    "current_step": "启动 OpenResty",
    "next_step": "标记为主机",
    "last_error": "",
    "step_summary": []
  },

  "logs": [
    {
      "seq": 1,
      "log_time": "2026-09-07 10:00:10",
      "log_level": "info",
      "stage_key": "master_online",
      "step_key": "master_openresty",
      "message": "开始执行启动 OpenResty",
      "detail": "systemctl start openresty"
    }
  ],
  "reported_at": "2026-09-07 10:00:10"
}
```

处理规则：

1. 校验单机归属和密钥。
2. 更新当前机器的 `ha_host_state`。
3. 有 `switch_task` 时，按 `switch_task_id` 更新 `ha_switch_task`。
4. 有 `logs` 时，按 `seq` 追加写入 `TASK_xxx.log`。
5. 根据当前机器最新状态刷新 `ha_pair`。

### 读取任务日志

接口：`GET /ha/api/local/switch-log?switch_task_id=TASK_20260907_100000_A1B2C3&offset=0`

返回日志文件新增内容和下一次读取偏移量：

```jsonc
{
  "status": true,
  "data": {
    "switch_task_id": "TASK_20260907_100000_A1B2C3",
    "log_path": "/www/server/jh-monitor/logs/ha_switch/TASK_20260907_100000_A1B2C3.log",
    "content": "[2026-09-07 10:00:10] [info] [master_online/master_openresty] 开始执行启动 OpenResty\n",
    "next_offset": 104
  }
}
```

## 数据流程

### 云监控创建单机归属

1. 运维人员进入云监控主备管理页面。
2. 输入一个主备管理 ID，例如 `HA_GROUP_001`。
3. 云监控创建 `ha_pair`，归属名称默认使用 `pair_id`。
4. 云监控生成并保存归属密钥。
5. 页面显示“等待当前机器上报”。

### 当前机器插件绑定归属

1. 在当前机器的主备管理插件填写本机 ID、`pair_id` 和云监控地址。
2. 插件调用注册接口，云监控写入当前机器的 `ha_host_state`。
3. 当前机器首次上报后，云监控直接展示该机器的主备角色和状态。
4. 本阶段不注册备用机，也不等待备用机上报。

### 插件上报切换过程

1. 插件创建本地 `TASK_` 切换任务后，先上报任务 `pending` 状态。
2. 每个步骤开始时，上报 `current_step`、`status_text` 和新增日志。
3. 每个步骤完成或失败时，更新 `ha_switch_task`、`ha_host_state` 和云监控日志文件。
4. 插件切换结束时上报 `success` 或 `failed`，并写入最终角色和自检结果。
5. 云监控列表和任务详情展示当前机器的最新状态与日志。

## 当前机器状态计算

1. 当前机器没有上报：`unknown`，显示“等待当前机器上报”。
2. 当前机器正在切换：`switching`，显示“当前机器名 + current_step”。
3. 当前机器切换失败：`danger`，显示“当前机器名 + last_error”。
4. 当前机器自检异常：`warning` 或 `danger`，显示对应自检摘要。
5. 当前机器角色为 `master` 或 `standby` 时，直接展示对应角色。
6. 当前机器角色和自检均正常：`normal`，显示“状态正常”。
7. 本阶段不根据其他机器计算双主、双备、一主一备或对端离线状态。

## 实施范围

当前云监控代码使用 SSH 版本的 `ha_switch_run` 和 `ha_switch_event`，本方案需要新增单机版专用的：

- `ha_switch_task` 表。
- 单机归属创建、当前机器注册、状态上报、日志读取接口。
- `ha_host_state.switch_task_id` 字段。
- 云监控单机归属创建页面和本地版展示逻辑。

当前本地插件仅保存绑定信息和本机状态，尚未调用云监控接口；接入顺序应为：先完成云监控单机归属创建和注册接口，再实现当前机器的状态、任务和日志上报。两台机器场景后续另行扩展。
