## Context

`ha_manager_local` 当前通过 systemd 状态判断 OpenResty 是否处于运行状态，并可直接停止、禁用和 mask OpenResty。总览和关闭动作均没有连接量信息。

OpenResty 默认配置提供仅本机访问的 `/nginx_status`，并启用了 `stub_status`。该状态页会返回 `Active connections`、`Reading`、`Writing`、`Waiting` 等实时连接指标。但当前已安装配置的监听端口可被本机配置修改；例如当前运行环境的状态页监听在 82 端口，而既有 OpenResty 插件的 `run_info` 固定请求 80 端口，无法可靠复用。

该变化涉及本地主备后端状态模型、服务关闭接口、总览展示与危险操作确认流程，需要在实施前明确采集失败和快照时效的行为。

## Goals / Non-Goals

**Goals:**
- 为 `ha_manager_local` 提供结构化、可诊断的本机 OpenResty 连接快照。
- 在总览显示当前活动连接及 Reading、Writing、Waiting 分类，并明确这是连接数而不是用户数。
- 关闭对外服务前展示最近快照和中断风险，要求操作员明确确认。
- 在真正停止 OpenResty 前再次采集快照，将该次快照写入关闭结果和操作日志。
- 当 OpenResty 已停止、状态页不可访问、端口无法发现或响应格式异常时，保持总览和关闭动作可用，并提供原因。
- 保持 `/nginx_status` 仅限本机访问，不增加外部监听端口、认证配置或第三方依赖。

**Non-Goals:**
- 不统计去重后的独立访问用户、IP 数、会话数、业务请求数或未来一段时间的流量预测。
- 不等待连接自然排空，也不改变现有“关闭对外服务”停止、禁用、mask OpenResty 的语义。
- 不采集或上报客户端地址、请求路径、请求内容等可能包含敏感信息的数据。
- 不在本次变更中改造其他插件或把状态页公开给外部网络。

## Decisions

1. **以活动连接快照衡量即时影响范围。**
   后端返回 `active`、`reading`、`writing`、`waiting`、`collected_at`、`available` 和不可用原因；界面使用“当前活动连接”命名，并在关闭确认中说明这只是即时连接快照，不等于真实用户数。
   替代方案是统计访问日志中的 IP 或会话。该方案无法准确反映正在受影响的连接，还会引入日志格式、反向代理、多用户 NAT 和隐私处理问题。

2. **在 `ha_manager_local` 内独立实现状态页发现和解析。**
   采集器先确认 OpenResty 已运行，再读取已安装的 `/www/server/openresty/nginx/conf/nginx.conf`，定位包含 `location /nginx_status` 的本机状态 server 块，提取其 `listen` 端口；随后以 `127.0.0.1` 和短超时访问状态页。响应采用字段名和正则校验解析，拒绝将普通 HTML 或截断文本当成有效指标。配置发现失败时仅尝试兼容的 80 端口回退，并在结果中记录失败原因。
   替代方案是调用现有 OpenResty 插件 `run_info`。它目前将端口固定为 80 且按 token 下标解析响应，无法处理实际端口调整或错误页面，因此不作为此安全提示的依赖。此次不改变 OpenResty 插件公共接口，以保持范围收敛。

3. **关闭动作采用“前端预览 + 后端关闭前复采”的双快照流程。**
   点击“关闭对外服务”后，前端先请求连接快照，在确认弹窗中展示。操作员确认后调用现有关闭接口；该接口在开始停止前再次采集快照，并把这次执行前快照随结果返回和写入操作日志。
   替代方案是仅在前端采集一次并将其回传给后端。该方案的快照可能过期且客户端参数不应作为审计数据来源。

4. **采集失败降级为可确认的风险提示，不阻断关闭。**
   如果状态页不可用，关闭确认弹窗必须显示“当前连接数暂时无法获取”和原因摘要，仍要求操作员确认。后端继续执行既有关闭逻辑，并在结果日志中记录采集失败。
   替代方案是因无法读取连接数而禁止关闭。这会削弱紧急下线能力，且 OpenResty 异常时恰恰可能无法读取状态页。

5. **总览按需采集连接快照，不在页面中轮询。**
   `get_state` 只返回总览基础状态，页面首次加载和已有刷新流程会单独请求连接快照；不新增短周期轮询、历史库或图表。
   替代方案是每秒轮询或持久化时序数据。这些能力超出本次“操作前影响提示”的目标，并会增加服务器开销和状态页自身连接对指标的干扰。

6. **连接详情说明 keep-alive 的短暂留存机制。**
   详情列表展示的是当前已建立 TCP 连接，其中可能包含已经完成网页请求、但仍由 HTTP keep-alive 保持的空闲连接。后端从当前 OpenResty 主配置读取 `keepalive_timeout` 的首个超时参数，将解析后的文本一并返回；配置缺失、读取失败或格式不支持时明确标识为未能识别，不用固定默认值代替。

7. **总览与连接快照分离加载。**
   前端等待基础状态和流程配置完成后一次性绘制总览，再异步调用 `get_connection_snapshot` 回填连接区域；采集中显示固定文案，失败后只在该区域展示原因，不影响已展示的其他总览内容。

8. **自检与基础状态分离加载。**
   `get_state` 返回主备、服务、云监控和流程等基础状态，不同步执行耗时的健康检查；总览先按基础状态完成显示，自检行再单独请求 `health_check` 并更新。`get_state` 跳过自检时只影响本次响应，不清除状态文件中已缓存的自检结果。

9. **基础状态等待期间展示总览骨架屏。**
   在基础状态和流程配置尚未完成时，前端显示与总览一致的标题、操作区和状态行占位，使用低对比灰色脉冲动画提示加载；基础数据完成后整体替换为实际总览，连接快照和自检仍按各自异步流程回填。

10. **兼容被 include 的状态页配置。**
   状态页端口发现递归读取 OpenResty 主配置引用的 `include` 文件，兼容 `stub_status;` 与 `stub_status on;`。配置发现失败时读取实际由 OpenResty 监听的端口作为候选，并仍严格校验响应格式；普通 HTTP 服务不会被解析为连接指标。已定位状态页端口返回的底层网络异常转换为中文原因摘要，避免将 Python 英文错误直接暴露在页面上。

## Risks / Trade-offs

- [风险] `stub_status` 的请求本身会占用一个短暂连接，且连接状态瞬时变化。 → 将其描述为即时快照和粗略影响范围，不承诺精确用户数或零误差。
- [风险] 管理员可修改 OpenResty 配置，导致状态页路径、监听方式或访问限制变化。 → 配置定位和响应解析失败时返回结构化不可用状态，并保留关闭流程。
- [风险] 一个监听端口可能存在多个虚拟主机，使用错误 Host 会取得普通页面。 → 请求强制使用本机回环地址和 `Host: 127.0.0.1`，且只接受符合 `stub_status` 字段格式的响应。
- [风险] 确认弹窗中的预览与实际停止前状态不同。 → 后端在实际关闭前复采，并以该复采结果作为日志和返回数据中的执行快照。
- [风险] 总览读取多了一次本机 HTTP 请求。 → 仅在现有状态加载时采集，设置短超时，采集异常不影响其他健康检查和页面渲染。
- [风险] 连接关闭受客户端行为、请求协议和服务端配置共同影响。 → 文案使用“通常会断开”，不承诺连接必然在该时刻消失。

## Migration Plan

1. 发布后端连接快照采集器和状态字段，默认在状态页不可用时返回 `available=false`，保持旧前端兼容。
2. 发布总览连接指标与关闭确认弹窗，验证运行、已停止、端口非 80、状态页异常四种情况。
3. 验证关闭前后端复采快照会记录在动作日志，确认关闭流程、OpenResty 自检和切换流程不发生回归。
4. 如需回滚，前端可忽略新增字段，后端移除快照采集调用即可恢复原有服务控制语义；不涉及数据迁移或外部配置变更。
