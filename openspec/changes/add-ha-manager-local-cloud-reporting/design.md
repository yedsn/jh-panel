## Context

`ha_manager_local` 已具备本机角色、自检、分步骤切换任务和步骤日志，但其云监控配置目前只保存地址及归属信息，`report_state` 不发送远程请求。云监控需要在不依赖备用机的前提下，保存并展示一台机器的最新状态和切换过程。

本设计覆盖云监控服务与本地插件两个边界。云监控使用 SQLite 保存可查询的状态与任务摘要，使用文件保存任务日志正文；插件继续以本机状态和步骤日志为事实来源。现阶段不改变 `ha_manager_ssh` 的协议或流程。

## Goals / Non-Goals

**Goals:**
- 让云监控先创建唯一的单机归属，再允许一台本地版插件注册、认证和上报。
- 持久化当前机器的角色、自检、在线状态和最近切换任务，并在云监控中展示其最新状态。
- 使状态、任务摘要和日志增量上报能够重试且不会造成重复日志。
- 让本地插件在绑定后静默保存归属密钥，并按配置周期及切换状态变化上报。

**Non-Goals:**
- 不注册、查询、等待或判断备用机；不计算双主、双备、一主一备或对端离线。
- 不提供云监控发起角色切换、暂停、继续、取消或任务领取能力。
- 不把完整切换日志写入 SQLite，也不迁移 SSH 一键版的云监控协议。
- 不改变本地插件的本机切换步骤、执行脚本或健康检查定义。

## Decisions

1. **以 `pair_id` 表示单机归属，以 `pair_id + host_id` 表示当前机器状态。**
   云监控创建 `ha_pair` 时生成高熵 `api_secret`，`pair_name` 固定默认 `pair_id`。注册和报告均须验证该归属与密钥；同一主机重复注册更新身份和注册时间，不需要存在对端。创建响应仅在创建时向管理人员返回密钥；受信部署通过本地插件的后端专用配置入口将密钥写入 `config.json`（权限 `0600`）。该入口不在页面渲染或普通配置响应中返回密钥，插件页面不增加密钥输入或展示项。
   替代方案是让注册接口无密钥或根据 IP 自动授权。两者会使任意主机能够加入归属，不满足上报鉴权要求。

2. **SQLite 保存实体摘要，文件保存日志正文。**
   `ha_pair` 保存归属、派生状态、密钥和时间；`ha_host_state` 保存最新本机报告，包括 `switch_task_id`；`ha_switch_task` 保存每次任务的摘要、步骤概览和日志文件路径。数据库初始化必须可重复执行，并设置 `pair_id`、`pair_id + host_id`、`switch_task_id` 的唯一约束。任务日志写入 `/www/server/jh-monitor/logs/ha_switch/TASK_<id>.log`，日志读取 API 用字节偏移量返回新增内容。
   替代方案是将每条日志建表。该方案会增加高频日志写入、查询与保留成本，且与文件化日志要求冲突。

3. **使用任务侧车序号索引确保日志幂等。**
   每个任务在日志目录维护仅含已接收 `seq` 的受限权限索引文件，例如 `TASK_<id>.seq.json`。报告处理器先验证 `switch_task_id`、正整数 `seq` 和归属匹配，再按 `seq` 排序写入未记录的项，更新索引后追加格式化日志行。重复的 `(switch_task_id, seq)` 必须忽略而不重复写入；同批次日志可乱序到达，缺号不得阻止较大序号写入。索引写入采用临时文件替换，并与日志追加置于同一任务写锁中。
   替代方案是只保存最大序号，或从日志文件扫描序号。最大序号会在乱序重试时丢失日志；扫描会随日志增长退化且难以可靠解析。

4. **用明确的优先级从当前机器最新快照计算归属状态。**
   云监控在成功注册及每次报告后刷新 `ha_pair`：未有有效主机上报为 `unknown`；切换运行中为 `switching`；切换失败或主机离线为 `danger`；自检 `danger`/`warning` 保留对应级别；角色为 `master` 或 `standby` 且自检正常时为 `normal`。`status_text` 依次采用等待上报、机器名加当前步骤、最近错误、自检摘要或角色/正常摘要。所有判断只读取该 `pair_id` 的当前机器状态，不查询其他机器。
   替代方案是在展示时临时计算。持久化派生结果使列表查询稳定且无需在每个读取路径重复业务规则。

5. **报告 API 接受一个原子快照，但允许缺省任务和日志。**
   `POST /ha/api/local/report` 验证归属、密钥、机器标识和枚举字段，然后在事务内更新主机状态与可选任务摘要，再处理日志文件并刷新归属状态。没有 `switch_task` 或 `logs` 的心跳报告仍有效；有日志时必须关联请求中的 `switch_task.switch_task_id` 或已保存的同机当前任务，不能把日志写到其他归属或其他主机的任务。
   替代方案是拆分多个上报接口。单个原子快照更适合插件在步骤边界上报，也减少状态和任务短暂不一致的窗口。

6. **云监控以只读视图展示单机状态和任务详情。**
   管理页创建归属并显示等待上报、当前主机、角色、自检、切换摘要和最近上报时间；任务详情通过日志读取 API 轮询追加内容。页面和 API 不出现切换角色、任务控制、备用机或一致性判断入口。
   替代方案是复用 SSH 版的双机控制界面。该界面的调度与对端语义会误导本地版运维流程。

## Risks / Trade-offs

- [Risk] 归属密钥若被泄露，未授权机器可伪造该归属的上报。 → 密钥必须使用安全随机源生成，数据库与插件配置采用仅服务账户可读权限，接口响应及运行日志不得回显密钥。
- [Risk] 文件追加在进程并发或意外中断时可能损坏日志或索引。 → 按任务加锁，索引通过临时文件原子替换，日志行一次写入并在启动/读取时容忍末尾不完整行。
- [Risk] 云监控未能接收报告时，页面可能显示过期的正常状态。 → 列表应展示 `last_report_at`；可在后续变更中基于超时阈值引入离线判定，本变更只存储插件主动报告的 `online_status`。
- [Risk] 一台机器可被多次注册到同一归属。 → 允许同 `host_id` 幂等更新；页面以最新状态展示且不推断存在多机关系。
- [Risk] 密钥在复制到本机的引导阶段可能被误写入普通日志。 → 专用配置入口接收后立即写入受限权限配置，接口响应、前端状态和运行日志均只报告“密钥已配置”而不输出其值。

## Migration Plan

1. 为云监控 SQLite 数据库增加幂等建表与索引逻辑，并创建受限权限的 HA 日志目录。
2. 实现归属创建、注册、报告和增量日志读取接口，先以接口测试覆盖认证、幂等及状态计算。
3. 增加云监控单机归属列表、详情及日志查看页面，只读取新接口和数据模型。
4. 为 `ha_manager_local` 增加后端专用的密钥受限保存、注册、周期报告及切换过程触发报告；在连接失败时保留本机任务继续执行并记录上报失败。
5. 使用单机环境验证首次注册、空心跳、运行中任务、失败任务、重复日志和日志偏移读取。
6. 回滚时停止插件上报并移除云监控页面/路由；保留 SQLite 表和日志文件以便审计，不影响 SSH 版插件。
