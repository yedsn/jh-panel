## ADDED Requirements

### Requirement: VM 资源报告入口与模块选择
VM OS 工具 SHALL 将“服务器资源分析报告”作为服务器状态检查菜单的第一项，现有菜单项依次后移，并通过现有 Python 脚本运行机制支持本地脚本和远程下载两种模式。报告脚本 SHALL 允许用户选择本次要采集的模块，并在采集前展示执行摘要。交互式选择 SHALL 使用 `dialog` 复选菜单，以空格勾选或取消、回车确认，并默认只勾选 CPU 和内存。

#### Scenario: 状态检查菜单顺序
- **WHEN** 用户打开 VM 服务器状态检查菜单
- **THEN** “服务器资源分析报告”显示为编号 1
- **AND** 原有状态检查工具保持原有相对顺序并从编号 2 开始依次后移

#### Scenario: 交互式复选菜单选择模块
- **WHEN** 用户在终端直接运行资源报告脚本
- **THEN** 系统以复选菜单列出全部模块，按空格切换勾选状态，按回车确认
- **AND** CPU 和内存默认处于勾选状态，系统概要、磁盘、网络、硬件和主动测试默认不勾选
- **AND** 用户取消菜单时不生成报告，并以成功状态退出

#### Scenario: 使用默认报告模块
- **WHEN** 用户在复选菜单中直接回车确认，或非交互运行未提供模块参数
- **THEN** 系统只采集 CPU 和内存模块
- **AND** 系统显示采样时长、目录扫描范围、输出位置和未启用的主动测试

#### Scenario: 缺少 dialog 时自动安装或回退
- **WHEN** 运行脚本的系统未安装 `dialog`
- **THEN** 系统按当前发行版尝试自动安装该软件包
- **AND** 自动安装失败时输出适用于当前系统的手动安装命令，并回退到文本编号选择
- **AND** 回退不影响已选模块的采集和报告生成

#### Scenario: 自定义报告模块
- **WHEN** 用户输入逗号分隔的模块编号或通过命令行参数指定模块
- **THEN** 系统只运行有效且已选择的模块
- **AND** 无效模块输入得到明确提示，不被静默解释为其他模块

#### Scenario: 本地与下载模式运行
- **WHEN** 入口分别在 `USE_PANEL_SCRIPT=true` 和默认远程下载模式下运行
- **THEN** 两种模式均通过 `download_and_run_py` 启动同一资源报告脚本
- **AND** 两种模式提供一致的模块、参数和报告输出行为

### Requirement: 系统概要与采样上下文
资源报告 SHALL 记录能够解释采集结果的服务器概要和采样上下文，包括主机、系统、内核、运行时间、CPU 核数、内存总量、虚拟化信息、报告时间、所选模块和实际采样窗口。

#### Scenario: 生成报告上下文
- **WHEN** 任意资源报告运行
- **THEN** 所有输出格式均包含主机名、操作系统、内核、运行时间、CPU 逻辑核数、内存总量、开始与结束时间
- **AND** 报告列出已完成、已跳过和失败的模块

#### Scenario: 部分概要信息不可用
- **WHEN** 某项系统概要信息在当前虚拟机或权限下不可读取
- **THEN** 系统将该项标记为 `unknown` 并继续采集其他项目

### Requirement: CPU 使用分析与进程排行
资源报告 SHALL 在可配置的短时采样窗口内计算系统 CPU 使用率、负载与进程 CPU 排行，并区分平均值和峰值，避免仅用单次快照推断持续占用。

#### Scenario: 计算 CPU 采样指标
- **WHEN** 用户选择 CPU 模块且采样完成
- **THEN** 报告包含采样时长、系统 CPU 平均使用率、峰值使用率以及 1、5、15 分钟负载
- **AND** 进程排行包含 PID、用户、命令、平均 CPU、峰值 CPU 和有效采样次数

#### Scenario: 采样期间进程退出
- **WHEN** 排行候选进程在采样期间退出或对应 `/proc` 数据消失
- **THEN** 系统忽略无法继续读取的样本并保留其他有效结果
- **AND** 单个进程消失不会导致 CPU 模块或整份报告失败

#### Scenario: 自定义采样和排行数量
- **WHEN** 用户指定采样时长、采样间隔或排行数量
- **THEN** CPU 报告按照有效参数运行并在报告中记录实际参数

### Requirement: 内存与 Swap 使用分析
资源报告 SHALL 输出总内存、已用内存、可用内存、缓存、Swap 和进程实际内存排行，并优先使用可用内存判断系统内存压力。

#### Scenario: 生成内存排行
- **WHEN** 用户选择内存模块
- **THEN** 报告包含内存总量、已用量、可用量、可用比例、缓存以及 Swap 总量和已用量
- **AND** 进程排行包含 PID、用户、命令、RSS 实际内存和内存占比

#### Scenario: Linux 缓存占用较高但可用内存充足
- **WHEN** 文件缓存较高且系统报告的可用内存仍高于警告阈值
- **THEN** 系统不会仅因缓存较高将内存判定为警告或严重

### Requirement: 文件系统容量与安全目录排行
资源报告 SHALL 输出文件系统容量和 inode 使用情况，并对用户选择的扫描根目录生成本地目录空间排行。目录扫描 MUST 不进入远程、分布式、容器或系统特殊挂载，并 MUST 受到文件系统边界、深度和超时限制。

#### Scenario: 排除远程和分布式挂载
- **WHEN** 扫描范围内包含 `nfs`、`nfs4`、`cifs`、`smb3`、SSHFS、Ceph、GlusterFS、rclone 或其他被识别为远程的挂载点
- **THEN** 系统不读取该挂载点内部内容
- **AND** 报告列出挂载路径、文件系统类型和“远程或分布式挂载”排除原因

#### Scenario: 排除特殊和容器文件系统
- **WHEN** 扫描范围内包含 `proc`、`sysfs`、`devtmpfs`、`tmpfs`、`overlay`、`squashfs`、`nsfs`、`tracefs` 或其他特殊文件系统
- **THEN** 系统不进入这些挂载点
- **AND** 报告将其标记为特殊或容器文件系统

#### Scenario: 统计本地独立数据盘
- **WHEN** 扫描范围内包含挂载在子目录的本地块设备文件系统
- **THEN** 系统将父文件系统和该本地文件系统作为独立扫描边界分别统计
- **AND** 合并排行时不重复计算该本地挂载点的数据

#### Scenario: 生成目录空间排行
- **WHEN** 本地目录扫描在限制内完成
- **THEN** 报告按字节数降序展示配置数量的目录或文件、格式化大小、所属文件系统和扫描根
- **AND** 报告记录扫描深度、耗时、完成状态和自定义排除路径

#### Scenario: 目录扫描超时或权限不足
- **WHEN** 某个扫描任务达到超时、目录无法读取或扫描命令失败
- **THEN** 系统停止或跳过受影响的扫描任务并继续其他模块
- **AND** 报告将该范围标记为不完整并保留已经获得的安全结果和错误原因

#### Scenario: 未知 FUSE 挂载
- **WHEN** 扫描范围包含无法确认是本地存储的未知 `fuse.*` 挂载
- **THEN** 系统默认保守排除该挂载并在报告中说明原因

### Requirement: 磁盘实时读写分析
资源报告 SHALL 通过增量采样输出本地块设备的读取吞吐、写入吞吐、读取 IOPS 和写入 IOPS，并在兼容工具可用时补充等待时间、队列和利用率。该模块 SHALL 是只读观察，不得写入测试数据。

#### Scenario: 内核计数器采样可用
- **WHEN** 用户选择磁盘实时 I/O 模块且 `/proc/diskstats` 可读
- **THEN** 报告按设备输出采样期平均及峰值读取速度、写入速度、读取 IOPS 和写入 IOPS
- **AND** 报告区分物理设备和可识别的虚拟设备，避免将分区与父设备无说明地重复排行

#### Scenario: 增强 I/O 工具可用
- **WHEN** `iostat` 或兼容工具已安装且输出可解析
- **THEN** 报告补充设备等待时间、队列长度和利用率

#### Scenario: 增强 I/O 工具缺失
- **WHEN** `iostat` 或 `iotop` 等增强工具未安装
- **THEN** 系统尝试通过当前系统包管理器安装对应工具包
- **AND** 安装失败时仍使用内核计数器生成基础磁盘 I/O 报告，将增强指标标记为 `unknown`，并在报告中记录失败原因和手动安装命令

### Requirement: 网络状态与实时流量分析
资源报告 SHALL 输出有效网卡的状态、地址、链路速率、实时接收和发送速度，以及错误和丢包增量，并明确区分网卡流量、链路协商速率和可选外网测速。

#### Scenario: 生成网卡实时流量
- **WHEN** 用户选择网络模块且网卡统计接口可读
- **THEN** 报告按网卡输出状态、地址、平均与峰值接收速度、平均与峰值发送速度、错误和丢包增量
- **AND** 默认排除回环接口，对物理、Bond、Bridge 或用户明确指定的接口保留类型说明

#### Scenario: 链路工具不可用
- **WHEN** `ethtool` 不存在或当前接口不支持查询
- **THEN** 系统在采集前尝试自动安装 `ethtool`
- **AND** 安装失败或接口不支持时继续报告可获得的流量、地址和错误信息，将链路协商速率标记为 `unknown`，并记录依赖安装结果

#### Scenario: 观察到网络错误或丢包增长
- **WHEN** 采样期间任一有效网卡的错误或丢包计数增加
- **THEN** 分析结论引用接口名、增量值和采样窗口，并给出警告或严重级别

### Requirement: 可选基础硬件健康信息
资源报告 SHALL 允许用户选择基础硬件模块，输出可读取的 CPU 型号、块设备、磁盘型号、容量、温度和 SMART 摘要；在虚拟机或权限受限环境中不可用的项目 SHALL 明确标记为未知。

#### Scenario: 硬件信息可用
- **WHEN** 用户选择硬件模块且对应 sysfs 或系统工具可用
- **THEN** 报告输出 CPU 型号以及磁盘设备、类型、容量、型号和可获得的健康信息

#### Scenario: 虚拟机无法访问 SMART 或传感器
- **WHEN** 当前环境不暴露 SMART、温度或物理硬件信息
- **THEN** 系统说明该指标在当前环境不可用并继续生成其余报告
- **AND** 不可用不得被渲染为“健康”或零值正常

### Requirement: 主动性能测试保护
磁盘性能测试和外网测速 SHALL 作为独立的主动测试模块，默认不选择。系统 MUST 在执行前展示资源影响并获得明确确认；非交互运行 MUST 需要单独的显式允许参数。

#### Scenario: 默认运行不执行主动测试
- **WHEN** 用户接受默认模块或未提供主动测试允许参数
- **THEN** 系统不运行磁盘性能测试和外网测速
- **AND** 报告将这两个模块记录为未选择或已跳过

#### Scenario: 用户取消主动测试
- **WHEN** 用户选择主动测试但在风险确认处拒绝或取消
- **THEN** 系统不执行对应测试并继续生成其他已选报告
- **AND** 报告记录用户取消的模块

#### Scenario: 磁盘测试目录不安全
- **WHEN** 用户选择的磁盘测试目录不可写、属于远程或被排除文件系统、或可用空间不足
- **THEN** 系统拒绝执行磁盘性能测试并说明具体原因

#### Scenario: 磁盘测试文件清理
- **WHEN** 磁盘性能测试成功、失败或被中断
- **THEN** 系统尝试删除本次创建的测试文件
- **AND** 如清理失败，终端和最终报告均突出显示残留文件的绝对路径

#### Scenario: 主动测试工具缺失
- **WHEN** `fio` 或受支持的外网测速工具未安装
- **THEN** 系统仅在对应主动测试已获得明确确认后尝试自动安装所需工具
- **AND** 安装失败时将对应模块标记为跳过，并在终端及报告中列出失败原因和手动安装命令

### Requirement: 依赖工具自动安装与报告
资源报告 SHALL 根据本次所选模块检查所需系统工具，并自动安装缺失软件。系统 MUST 在安装失败时继续可降级的报告流程，并在终端、TXT、JSON 和 HTML 中提供可操作的手动安装说明。

#### Scenario: 所需工具已经存在
- **WHEN** 本次所选模块需要的命令已经可执行
- **THEN** 系统不重复安装对应软件包
- **AND** 依赖结果将该工具记录为 `present`

#### Scenario: Debian 系自动安装成功
- **WHEN** 所需工具缺失且系统可使用 `apt-get`
- **THEN** 系统刷新一次软件源并使用非交互参数安装本次缺失的软件包
- **AND** 安装后重新检查命令，将成功可执行的工具记录为 `installed`

#### Scenario: RHEL 系自动安装成功
- **WHEN** 所需工具缺失且系统可使用 `dnf` 或 `yum`
- **THEN** 系统使用可用的包管理器和非交互参数安装本次缺失的软件包
- **AND** 安装后重新检查命令，将成功可执行的工具记录为 `installed`

#### Scenario: 自动安装失败
- **WHEN** 包管理器不可用、权限不足、软件源失败、包不存在或安装后命令仍不可执行
- **THEN** 系统将工具记录为 `failed`，包含包名、错误摘要和适用于当前系统的手动安装命令
- **AND** 可降级模块继续采集，不可执行的主动测试标记为跳过，整份报告仍尝试生成

#### Scenario: 依赖结果出现在所有报告格式
- **WHEN** 依赖检查和自动安装流程结束
- **THEN** 终端摘要、TXT、JSON 和 HTML 均展示工具、所属模块、状态、包名及失败时的手动安装命令

### Requirement: 基于证据的分级分析
资源报告 SHALL 根据可配置阈值产生严重、警告和提示三级结论。每条结论 SHALL 包含指标证据、当前值、阈值或判定依据、采样窗口以及建议，并将缺失或失败数据标记为未知而非正常。

#### Scenario: 指标超过阈值
- **WHEN** CPU、负载、内存、Swap、文件系统容量、inode、磁盘 I/O 或网络错误指标达到配置阈值
- **THEN** 系统在摘要中按严重、警告、提示顺序列出问题
- **AND** 每条问题能够定位到对应报告模块和原始指标

#### Scenario: 单次采样结论
- **WHEN** 系统根据本次短时采样生成结论
- **THEN** 文案限定为“本次采样期间”或“当前观察到”
- **AND** 系统不将单次采样描述为长期趋势或确定的应用根因

#### Scenario: 指标采集失败
- **WHEN** 指标因命令缺失、权限不足、解析失败或超时而不可用
- **THEN** 该指标状态为 `unknown` 或 `skipped` 并带有原因
- **AND** 该指标不参与正常状态计数

### Requirement: 多格式报告与故障隔离
资源报告 SHALL 从同一份结构化数据生成终端摘要、TXT、JSON 和自包含 HTML 文件。单个模块失败不得阻止其他模块采集或报告落盘；默认输出目录不可写时 SHALL 回退到安全的临时目录。

#### Scenario: 成功生成报告文件
- **WHEN** 至少一个所选模块完成且输出目录可写
- **THEN** 系统生成包含主机名和时间戳的 TXT、JSON 和 HTML 报告
- **AND** 同一报告中的模块状态、问题数量和关键指标在三种格式中保持一致

#### Scenario: 默认输出目录不可写
- **WHEN** `/www/server/log/server_resource_report/` 无法创建或写入
- **THEN** 系统回退到 `/tmp/server_resource_report/`
- **AND** 终端输出和报告元数据明确记录回退后的目录及原因

#### Scenario: 单个模块失败
- **WHEN** 某个已选模块采集失败
- **THEN** 系统记录模块失败原因并继续运行其他模块
- **AND** 最终报告包含失败模块、成功模块和跳过模块汇总

#### Scenario: 防止半成品报告
- **WHEN** 系统写入任一最终报告文件
- **THEN** 系统先写入同目录临时文件并在完成后原子替换最终文件
- **AND** 初始化失败或完全无法创建输出文件时返回失败退出码

#### Scenario: 报告含严重问题
- **WHEN** 报告成功生成但分析发现严重问题
- **THEN** 系统在终端和报告中突出严重问题
- **AND** 仅发现资源问题本身不导致报告生成流程返回失败退出码
