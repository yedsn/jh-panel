## Context

VM 脚本库目前通过 `index__monitor.sh` 分别暴露进程快照、持续 TOP、`iotop`、`fio` 和当前目录空间导出。这些工具适合单项排查，但输出格式、交互方式和采样周期不一致，无法组合成一次可交付的资源诊断报告。`scripts/os_tool/pve/monitor__hardware_report.py` 已证明 Python 适合聚合采集、风险分析和多格式报告，但该脚本包含 PVE、IPMI、传感器及邮件等专用逻辑，不宜直接扩展为通用 VM 报告。

本变更面向 Linux VM/普通服务器管理员。实现需要兼顾交互运行和未来自动调用，允许部分系统工具缺失，避免资源报告本身给生产服务器制造不可控负载。目录空间分析尤其需要识别文件系统边界：本地独立数据盘应分别统计，而 NFS、SMB/CIFS 等远程挂载、容器 Overlay 和伪文件系统必须跳过。

## Goals / Non-Goals

**Goals:**

- 从 VM 状态检查菜单一次生成可选模块组成的服务器资源报告。
- 提供 CPU、内存、文件系统与目录空间、磁盘实时 I/O、网络实时流量及基础硬件信息。
- 对短时采样数据计算平均值、峰值和排行，并根据阈值形成可解释的三级结论。
- 安全扫描本地文件系统，自动排除远程、分布式、容器和伪文件系统挂载。
- 将被动诊断与会制造磁盘或网络负载的主动测试分开，并要求二次确认。
- 在单个采集模块失败时继续生成 TXT、JSON 和 HTML 报告，明确记录未知项和失败原因。
- 保持本地脚本模式与远程下载模式一致，不引入 Python 第三方运行时依赖。

**Non-Goals:**

- 不替代 Prometheus、Zabbix 等长期监控或历史趋势系统。
- 不自动修复报告发现的问题，也不终止高占用进程。
- 不改造现有 PVE 硬件健康报告或合并其 IPMI、通知和邮件流程。
- 第一版不提供定时任务、跨服务器汇总、报告上传或自动清理历史报告。
- 第一版不承诺识别应用层根因；分析结论只基于本次采样和系统可见指标。

## Decisions

### 使用独立 Python 脚本和统一报告数据模型

新增一个位于 `scripts/os_tool/vm/default/` 的 Python 脚本，由 `index__monitor.sh` 的第一项通过现有 `download_and_run_py` 入口执行，现有状态检查菜单项依次后移。脚本内部按系统概要、CPU、内存、磁盘容量、目录空间、磁盘 I/O、网络、硬件和主动测试划分采集器；各采集器返回统一结构，包括 `status`、原始指标、排行、采样信息、问题和错误。报告渲染器只消费这一结构，分别输出终端、TXT、JSON 和静态 HTML。

选择 Python 而不是继续编排多个 Shell 脚本，是因为短时采样、PID 聚合、挂载点归类、超时控制、JSON/HTML 渲染和错误隔离在 Python 中更易保持可测试性。实现只使用 Python 标准库；所选模块需要的系统工具缺失时，由脚本通过系统包管理器自动安装。现有单项 Shell 脚本保持不变，仍可用于持续观察。

### 按所选模块自动准备依赖工具

脚本在正式采集前根据所选且已确认的模块建立依赖清单，只安装当前运行需要的缺失工具。Debian/Ubuntu 使用 `apt-get`，RHEL/CentOS/Rocky/Alma/Fedora 优先使用 `dnf`、回退 `yum`；非 root 运行时使用可用的非交互 `sudo`，否则记录权限失败。映射至少包括 `iostat → sysstat`、`ethtool → ethtool`、`smartctl → smartmontools`、`fio → fio`、`speedtest-cli → speedtest-cli`、`ip → iproute2`、`findmnt → util-linux` 和 `du → coreutils`。

同一个包管理器运行中只刷新一次软件源，并尽量批量安装缺失包。安装后必须重新检查命令是否可执行，不能仅以包管理命令退出码判断成功。每个工具记录 `present`、`installed` 或 `failed` 状态、所属模块、包名、安装命令、错误摘要和适用于当前系统的手动安装命令。安装失败不阻止整份报告生成：存在内核或 sysfs 回退的模块继续运行，没有安全回退的主动测试标记为跳过。终端摘要、TXT、JSON 和 HTML 均包含依赖准备结果。

### 同时支持交互选择和非交互参数

交互式运行时复用 VM 脚本库既有的 `dialog` 复选菜单风格：用 `--checklist` 列出全部模块，空格勾选或取消、回车确认，默认勾选系统概要、CPU、内存和磁盘容量及目录占用排行这四类最常用模块，网络、硬件健康和主动测试默认不勾选。菜单通过 `/dev/tty` 读写，因此面板或管道场景下的标准输出仍然只包含报告文本。缺少 `dialog` 时先按当前发行版自动安装，安装失败则输出手动安装命令并回退到文本编号输入，保证任何环境下都能选择模块。用户取消菜单时不生成报告。

脚本同时提供命令行参数，用于指定模块、采样时长、排行数量、扫描根目录、扫描深度、超时、排除目录和输出目录，使后续自动化不依赖交互输入。非交互运行或未提供模块参数时，默认模块与复选菜单保持一致。

选择模块后先打印执行摘要，包括预计采样时间、目录扫描范围、输出位置和主动测试状态。普通只读采集不要求确认；选择磁盘性能测试或外网测速时必须分别显示影响并获得明确确认。非交互模式只有显式传入允许主动测试的参数时才执行，否则将其标记为跳过。

### 采用短时增量采样，而不是单次命令快照

CPU 总使用率通过 `/proc/stat` 的前后差值计算。进程 CPU 排行通过 `/proc/<pid>/stat` 的 CPU 时间增量聚合，记录采样期平均占用、峰值和命令；进程退出或权限不足时保留可获得的数据。内存排行读取进程 RSS 和总内存，输出实际内存和比例。默认采样 10 秒、每秒一次，允许参数覆盖。

磁盘实时 I/O 优先读取 `/proc/diskstats` 的前后差值计算读写吞吐和 IOPS，并在自动准备的 `iostat` 可用时补充 `await`、队列和利用率。网络速度通过 `/sys/class/net/<iface>/statistics` 前后差值计算收发平均值与峰值，链路、协商速度和错误/丢包从 `ip`、`ethtool` 和 sysfs 获取。自动安装失败时，核心报告仍使用内核和 sysfs 数据降级生成。

### 按文件系统边界执行目录空间排行

脚本优先使用 `findmnt` 获取源、目标和文件系统类型，失败时回退读取 `/proc/self/mountinfo`。挂载点按以下方式分类：

- 本地文件系统：包括常见块设备文件系统和可确认的本地设备映射；位于扫描范围内的本地独立挂载点分别作为扫描边界。
- 远程或分布式文件系统：至少包括 `nfs`、`nfs4`、`cifs`、`smb3`、`sshfs`/`fuse.sshfs`、Ceph、GlusterFS 和 rclone，全部排除。
- 特殊文件系统：包括 `proc`、`sysfs`、`devtmpfs`、`tmpfs`、`overlay`、`squashfs`、`nsfs`、`tracefs` 等，全部排除。

默认扫描根目录为 `/www`，允许用户改为 `/`、其他绝对路径或多个根目录。扫描每个本地文件系统时限制在本文件系统内，不穿越其他挂载点；如果范围内存在本地独立数据盘，则另行扫描该挂载点并合并排行，从而既避免重复计算，也不遗漏本地数据盘。

目录统计使用字节值排序，再格式化为人类可读单位。每个扫描任务具有最大深度、总超时和可取消的子进程；默认输出前 20 项。用户自定义排除路径在规范化后应用于扫描。报告必须列出扫描范围、完成或超时状态，以及每个被跳过挂载点的路径、类型和原因。

采用动态挂载类型识别而不是写死 `/mnt`、`/media` 等路径，因为远程存储可能挂在任意业务目录。也不简单使用单个 `du -x /`，因为那会遗漏其他本地文件系统。

### 主动测试独立、受控且可清理

磁盘性能测试与实时 I/O 观察是两个模块。性能测试仅在用户选择并二次确认后执行，之后才允许自动安装缺失的 `fio`。脚本要求用户选择测试目录，验证目录位于本地可写文件系统且不属于已排除挂载。测试使用有限时长和有限文件大小，报告测试配置，并确保成功、失败或中断时都清理测试文件。`fio` 自动安装失败时记录手动安装命令并跳过测试。

外网测速同样是独立模块，只在显式确认后自动安装或调用受支持的测速工具；安装失败或无法联网时记录为未知/跳过，不影响本地网络报告。报告明确区分“网卡当前收发速度”“链路协商速率”和“外网测速结果”。

### 分级分析保留证据并避免过度结论

分析器将问题分为严重、警告和提示。默认阈值覆盖 CPU、负载与核心数关系、可用内存、Swap、文件系统容量、inode、磁盘利用率与等待、网卡错误/丢包等，并允许命令行覆盖。每个结论包含指标、当前值、阈值、采样窗口和建议动作。

在分析结论之外，报告再生成一份供人快速浏览的概要信息，放在 TXT 和 HTML 正文的最前面，并同步输出到 JSON 和终端摘要。概要信息按严重、警告、提示排序汇总三类内容：达到阈值的指标风险、采集降级（模块失败、跳过、不完整、增强指标不可用、目录扫描未完成、主动测试残留文件）和依赖工具安装失败，另外记录输出目录回退。没有风险时输出一句“服务运行正常，继续保持！”，避免运维人员在长报告中逐段确认。概要信息与问题列表同源，只做聚合和排序，不引入新的判定逻辑。

单次报告只描述“本次采样期间”或“当前观察到”，不将瞬时数据表述为长期故障。工具缺失、权限不足、命令超时和不支持的硬件均作为 `unknown` 或 `skipped`，不误判为正常。发现严重问题不阻止报告落盘；只有无法创建任何输出文件或初始化失败才返回失败退出码。

### 报告输出采用同一份结构化数据

默认输出目录为 `/www/server/log/server_resource_report/`，不可写时回退到 `/tmp/server_resource_report/` 并在终端和报告元数据中提示。文件名包含主机名和时间戳；TXT 和 HTML 使用带时间戳文件，JSON 同时生成带时间戳文件和一个指向最新数据的稳定文件名。HTML 为自包含静态页面，不引用外部资源。

输出过程先写临时文件再原子替换最终文件，防止中断留下看似完整的半份报告。终端最后打印已生成文件、所选模块、跳过模块、失败模块和问题数量。

## Risks / Trade-offs

- [目录排行可能产生较高读取负载并运行较久] → 默认扫描 `/www`、限制深度和超时、显示扫描摘要，支持自定义范围；超时后保留已完成部分并标记不完整。
- [文件在扫描期间变化会使目录合计与 `df` 不完全一致] → 在报告中记录采样时间和扫描耗时，并将目录排行标为近似值。
- [挂载类型繁多，未知 FUSE 类型可能是远程存储] → 对未知 `fuse.*` 默认采取保守排除并记录原因，允许用户通过参数明确纳入本地路径。
- [短时采样无法代表长期趋势] → 报告明确采样窗口，结论限定为当前观察，不提供趋势性断言。
- [读取 `/proc/<pid>` 时进程可能退出或受权限限制] → 按 PID 独立容错，跳过消失的进程并记录权限受限数量。
- [`/proc/diskstats` 无法直接提供所有延迟指标] → 核心吞吐和 IOPS使用内核计数器；增强延迟指标仅在兼容的 `iostat` 可用时提供。
- [主动测试可能影响生产负载] → 默认不选、二次确认、有限时长与大小、验证本地文件系统、可靠清理，并允许随时取消。
- [HTML、TXT 与 JSON 内容可能逐渐分叉] → 三种格式只从同一份报告数据模型渲染，不在渲染层重新计算指标。

## Migration Plan

1. 新增资源报告脚本，不修改现有单项监控脚本。
2. 将资源报告作为 VM 状态检查菜单第一项，现有菜单项依次后移，并复用 `download_and_run_py`。
3. 在支持的 Linux VM 上验证默认模块、缺少增强工具、远程挂载、本地多数据盘、扫描超时和只读输出目录场景。
4. 验证主动测试默认不运行，并验证确认、取消、中断和临时文件清理。
5. 发布后如需回滚，仅移除菜单入口和新脚本；现有监控功能与数据不受影响。

## Open Questions

无阻塞性问题。首版采用 `/www`、10 秒采样、前 20 名和保守排除未知 FUSE 挂载作为默认值，均允许用户在运行时或通过参数覆盖。
