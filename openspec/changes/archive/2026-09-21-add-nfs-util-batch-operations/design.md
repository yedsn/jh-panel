## Context

`nfs-util` 的挂载列表当前没有选择状态。单项挂载和卸载由后端返回 shell 脚本，再通过面板全局 `execScriptAndShowLog` 执行并展示日志；单项自动挂载则由后端直接通过 shell 命令增删 `/etc/fstab` 行。

`jianghujs` 已提供列表复选框、全选和按已选 ID 执行批量动作的交互模式，但它的运行操作由后端逐项加入面板任务。NFS 操作需要保留现有实时日志体验，并谨慎处理 shell 参数和 `/etc/fstab`，因此只复用选择交互，不直接复制其后端执行方式。

## Goals / Non-Goals

**Goals:**

- 为 NFS 挂载列表提供与面板现有插件一致的多选、全选和批量操作交互。
- 通过一次日志任务顺序执行批量挂载或卸载，并记录每个条目的处理结果。
- 通过显式 `enable`/`disable` 操作批量修改自动挂载配置，保证混合状态和重复请求下结果一致。
- 对 shell 参数、挂载状态判断和 `/etc/fstab` 修改采用受控、可验证的处理方式。
- 复用单项和批量操作的底层构建逻辑，避免两套行为长期分化。

**Non-Goals:**

- 不增加批量删除。
- 不并行执行多个挂载或卸载命令。
- 不改变挂载记录的数据结构、导入导出方式或 NFS 服务端配置。
- 不引入任务队列、外部依赖或新的长期运行服务。
- 不自动删除本地挂载目录。

## Decisions

1. **沿用 `jianghujs` 的选择交互，但使用插件作用域内的选择器和状态。**
   列表增加表头全选框和逐行复选框，前端保存已选 ID。批量按钮在至少选择一项时显示；列表刷新后只保留仍存在于当前数据中的选择，并同步表头全选状态。所有 DOM 查询限定在 `.nfs-util-panel` 内，避免与面板或其他插件的 `.check` 元素互相影响。
   替代方案是直接复制 `jianghujs` 的全局选择器。该方式实现更快，但插件窗口内出现其他复选框时容易误选，也不利于后续维护。

2. **批量挂载和卸载通过一个后端批量脚本接口生成组合脚本。**
   新增批量脚本入口，接收逗号分隔的 ID 和 `mount`/`unmount` 动作。后端去重并按请求顺序读取记录，为每项生成独立日志段和命令段；浏览器只调用一次 `execScriptAndShowLog`，脚本按顺序执行全部条目。单项入口与批量入口复用挂载、卸载脚本构建辅助函数。
   替代方案是前端循环调用单项接口并打开多个日志任务。该方案会产生多个窗口或难以聚合的异步状态，也无法清楚展示整批结果。

3. **组合脚本在运行时检查实际挂载状态，并允许部分失败后继续。**
   每个条目使用精确目标路径检查，而不是对 `mount` 输出做字符串包含判断。已处于目标状态的条目输出“跳过”；目标路径存在冲突或命令失败的条目输出失败原因；后续条目继续执行。所有来自记录的服务器、共享路径和本地路径在进入 shell 前使用标准 shell quoting。
   替代方案是生成脚本时依赖列表接口返回的状态。列表状态可能在用户点击后发生变化，无法避免重复挂载或错误卸载。

4. **批量自动挂载使用显式、幂等的后端设置接口。**
   新增批量自动挂载入口，接收 ID 和 `enable`/`disable`。后端一次读取 `/etc/fstab`，按挂载记录生成规范配置行：开启时仅补充缺失行，关闭时仅删除完全匹配的配置行，保留注释、空行及其他挂载配置；处理完成后通过临时文件原子替换，并返回成功、跳过和失败摘要。单项切换可继续保留原有 UI，但底层应复用显式设置辅助函数。
   替代方案是对每个 ID 调用现有 toggle。选择项状态混合或页面状态过期时，toggle 会让最终状态不一致，且多次执行 `sed`/追加会增加重复和部分写入风险。

5. **对影响范围较大的批量动作进行确认，并在结束后刷新真实状态。**
   批量卸载、批量开启自动挂载和批量取消自动挂载执行前显示包含已选数量的确认信息；批量挂载可直接执行。脚本日志任务结束或自动挂载接口返回后刷新挂载列表，状态仍以后端对当前挂载表和 `/etc/fstab` 的读取结果为准。操作完成后保留有效选择，便于继续对同一批条目执行关联操作。
   替代方案是所有动作均立即执行。批量卸载和系统启动配置修改的影响面较大，缺少确认容易造成误操作。

6. **为前端脚本增加资源版本参数。**
   `index.html` 加载 `nfs-util.js` 时增加并更新 `v` 参数，确保升级后浏览器不会继续使用不包含批量能力的旧脚本。

## Risks / Trade-offs

- [风险] 一个组合脚本运行时间可能随选择数量增长。 → 顺序执行并持续输出条目级日志，不设置前端循环超时；不并行操作同一挂载子系统。
- [风险] 批量卸载可能因目录正在使用而失败。 → 不强制使用 lazy/force 卸载，记录失败并继续其他条目，保持现有卸载语义。
- [风险] `/etc/fstab` 写入中断可能影响系统启动配置。 → 单次读取和修改，写入同目录临时文件后原子替换；保留原文件权限，并在替换失败时返回错误而不报告成功。
- [风险] 已选记录在刷新期间被删除。 → 刷新后剔除不存在的 ID；后端仍对每个 ID 做存在性校验并报告跳过或失败。
- [权衡] 批量脚本对部分失败继续执行，整批不能作为事务回滚。 → NFS 挂载本身不适合跨多个目标做原子事务，条目级日志和最终状态刷新比回滚已成功操作更可控。

## Migration Plan

1. 发布兼容现有单项操作的后端辅助函数和两个批量入口，不修改已有挂载记录。
2. 发布前端复选框、批量按钮、确认流程和资源版本参数。
3. 验证单项挂载、卸载、自动挂载切换仍可工作，再验证混合状态的批量操作。
4. 回滚时恢复前端脚本和后端入口即可；变更不迁移数据。已写入 `/etc/fstab` 的配置均是插件原有格式，旧版本仍可识别和管理。
